## Project

Danmaku (탄막 게임) — a 2D bullet-hell game built with **Unity 6000.3.23f1**, URP 2D renderer, the new Input System, and DOTween. Commit messages, code comments and docs are in Korean. `.editorconfig`: UTF-8, LF.

`CODEBASE_GUIDE.md` (Korean, per-class reference) is generated by Copilot via `.github/workflows/docs.yml` (push a `docs` tag) from whatever commit was tagged, so it can lag behind the code — trust the source over it, and don't hand-edit it.

## Build / Run

- No CLI build, lint or test commands; open the project in the Unity Editor (matching version).
- Build Settings scenes: `Assets/01.Scenes/Online/Title.unity` → `Online/InGame.unity` (Title's start button calls `GameManager.LoadScene("InGame")` by string name). Scenes at the root of `01.Scenes/` (`BulletTest`, `EnemyTest`, `art-test`) are test-only.
- A run does not start on its own: nothing at runtime calls `StageRunner.StartRun()` or `StatusManager.Initialize()`. In play mode use the inspector buttons from `Editor/StageRunEditor` ("시작") and `Editor/StatusManagerEditor`.
- Unity Test Framework is installed but there are no tests.
- CI (`.github/workflows/build.yml`) builds **WebGL** with `game-ci/unity-builder` when a `v*` tag is pushed (or on manual dispatch); the bot commits the output into `docs/` (GitHub Pages) with `[skip ci]`. Never hand-edit `docs/`.
- **DOTween Pro is a paid asset and is gitignored** (`Assets/Plugins/Demigiant/DOTweenPro*`, `DemiLib`; only free DOTween is tracked). It must exist locally (Title scene uses DOTween Pro animations; defines `DOTWEEN;DOTWEENPRO` are set); CI copies it from the private `PrivateStorage` repo. Never commit it.

## Architecture

Scripts live in `Assets/02.Scripts/`, all compiled into `Assembly-CSharp` (no asmdefs). Asset folders are number-prefixed (`01.Scenes`, `02.Scripts`, `03.Textures`, `04.Materials`, `05.Prefabs`).

### Managers / singletons

`Core/SingletonBehaviour<T>`: `Instance` finds an active `T` in the scene, and if there is none it **instantiates the first `T` prefab in `Resources/ManagerObjects/`** (with a warning). So managers absent from a scene appear on first access — e.g. `StatusManager` and `InGameInputHandler` are not placed in InGame. Use `ExistingInstance` in teardown code (`OnDisable`/`OnDestroy`) to avoid spawning one. Duplicates destroy themselves in `Awake`; subclasses overriding `Awake` must call `base.Awake()`; `IsPersistent` enables `DontDestroyOnLoad` (`GameManager`).

### Timing

All gameplay runs in `FixedUpdate` (Fixed Timestep = 1/60) and moves with `Time.fixedDeltaTime`. Durations in data and code are **fixed frames**: wait with `yield return new WaitForFixedFrame(n)` (`Core/`) or the cached `GameManager.WaitForFixedUpdate`; `GameManager.FrameToSecond` converts frames for DOTween.

### Danmaku data (ScriptableObjects in `Assets/Datas/`, menus under Stage/Spell/Bullet)

```
StageData → PhaseData[] → EnemyChain[] → EnemyPattern
  EnemyPattern (struct: type, name, color, Body: BulletData, SpellCard[], spawn pos, first-burst wait)
    SpellCard (HP, TimeLimit) → BurstData[] (PresentPosition, WaitForFrame) → BulletPattern[]
      BulletPattern = BulletData + InitialBullet (color/pos/vel/torque) + BulletSequenceBase + WaitForFrame
```

There is no separate enemy asset: enemies are defined inline in `EnemyPattern` inside `PhaseData`, and an enemy's sprite and hit radius come from its `Body` BulletData (`BulletImage`, `Distance`).

### Runtime flow

- `StageRunner` walks phases/chains as a coroutine → `EnemyManager.SpawnEnemy` (pooled `05.Prefabs/EnemyPrefab` for `EnemyType.Common`, otherwise instantiates `BossPrefab` / `EnemyBoss`).
- `Enemy.StartPattern` runs each SpellCard, repeating `BulletManager.BurstChain(spell.Bursts, transform)` until HP ≤ 0 or `TimeLimit` frames pass, then `OnDie` → `EnemyManager.ReleaseEnemy`.
- `BulletManager.BurstChain`: a burst with `WaitForFrame > 0` also DOTween-moves the presenter to `PresentPosition` over that duration — **enemy movement is authored as bursts**; bursts with 0 wait only fire. Each BulletPattern spawns one bullet, then waits its own `WaitForFrame`.
- The player auto-fires its `playerBurst` (`Datas/Bursts/Player/l0`–`l5`) every 5 frames via `BulletPatternChain`.

### Bullets

- `Bullet` is a plain C# class (not a GameObject), pooled by `BulletManager` (`ObjectPool`, max 1024). `BulletManager.FixedUpdate` updates live bullets, releases dead / out-of-deadzone ones with in-place compaction (spawn order is preserved — render order depends on it), then calls `BulletCollision.Rebuild`.
- To destroy a bullet set `IsAlive = false`; never remove or reorder `ActiveBullets` elsewhere — the collision grid stores indices into that list until the next rebuild.
- `BulletCollision` is a static uniform grid per `BulletTag` (`Enemy`/`Player`); `Check`/`CheckAll` test a circle against circle bullets and lasers (`BulletData.Distance` = radius or laser length). The player checks `Enemy`-tag bullets; enemies check `Player`-tag bullets with `Body.Distance`.
- Movement: `BulletSequenceBase` (SO) → `ISequenceRunner` (`Start` once, `Next` per frame). `DefaultSequence` (linear + torque), `AccelateSequence` (curve to target speed, then acceleration), `TargettingSequence` (aims at the player on start; initial velocity = speed + angle offset), `SequenceBridge` (chains sequences at frame counts). Stateless runners share a static `Singleton`; stateful ones must be created per bullet.
- `BulletRenderer` draws `ActiveBullets` with `Graphics.DrawMeshInstanced`, batched per sprite in chunks of 1023, using a runtime copy of `04.Materials/Bullet01.mat` (shader `Custom/URP/Sprite Invert Multiply`). Meshes come from sprite vertices/UVs, so the tightly packed atlas `03.Textures/AtlasSet.spriteatlasv2` renders correctly. It only reads bullet data.
- The game camera renders into `03.Textures/InGame.renderTexture`, shown in the UI (the gameplay view is not the screen directly).

### Player / status / input

- `StatusManager`: HP, power (`decimal`), score, high score (`DataSaveLoad` → PlayerPrefs), exposed as serialized `UnityEvent`s (targeting `UIManager` setters) plus C# event wrappers. `Hit()` applies damage after 18 frames unless `TryUsePower` (bomb, −1) / `TryUseSemiPower` (−0.5) cancels it.
- `PlayerController` clamps movement between the `DeadzoneMinTr`/`DeadzoneMaxTr` transforms; a bomb calls `BulletManager.BulletClearing` (expanding clear radius) and grants 300 frames of invincibility, as does dying.
- Input: `PlayerInput` (*Invoke Unity Events*; actions in `Assets/Settings/InputSystem_Actions.inputactions`) and the on-screen `HoldButton`/`TapButton`/`InGameSwipe` call `InGameInputHandler` methods (`InvokeOnMove`, `ChangeSlowMoveState`, `InvokeOnUseBomb`, `InvokeOnUseSemiBomb`, `Swipe`). These bindings are serialized in `Resources/ManagerObjects/UIManager.prefab` and `Input Handler.prefab` — renaming the methods breaks them silently. Gameplay subscribes to `OnMove`/`OnUseBomb`/`OnUseSemiBomb`/`OnSwipe` and reads `IsSlowMoving`.
- `PlayerAnimation` drives the Animator int param `Right` (-1/0/1).

### Editor tools (`02.Scripts/Editor/`)

`BulletDataEditor` / `BurstDataEditor` (sprite, hitbox and burst previews), `DeadzoneGizmos` (scene-view rects for the player and bullet deadzones), and play-mode test inspectors `StageRunEditor`, `StatusManagerEditor`, `UIManagerEditor`.

### Not implemented yet

`PhaseData.Boss`, `StageData.BGM`/`StageTitle` (unused by `StageRunner`), `GameManager.OpenOptionPanel`, an input binding for semi-bomb, and starting a stage outside the editor buttons.
